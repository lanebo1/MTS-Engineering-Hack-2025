# Общая цель, суть и решаемые проблемы системы безопасности контейнеров МТС

## Общая цель проекта

### Миссия системы
**Обеспечить комплексную безопасность контейнеризированных приложений МТС, предотвращая развертывание неподписанных образов и защищая критическую инфраструктуру телеком-оператора от киберугроз. Сканирование уязвимостей отключено в демо-версии.**

### Видение
Создать **zero-trust платформу безопасности контейнеров**, которая интегрируется seamlessly в процессы CI/CD и Kubernetes, обеспечивая автоматическую защиту от современных угроз цепочки поставок программного обеспечения.

## Сущность проекта

### Что представляет собой система
Комплексная **платформа безопасности контейнеров** для телеком-инфраструктуры, построенная на принципах:

- **Shift-Left Security**: Проверки безопасности на ранних этапах CI/CD
- **Defense-in-Depth**: Многоуровневая защита от различных типов угроз
- **Zero-Trust Architecture**: Никакое развертывание не доверяется по умолчанию
- **Compliance-as-Code**: Автоматизированное обеспечение соответствия регуляциям

### Архитектурная парадигма
**Admission Control + Policy Engine + Signature Verification** *Security Scanning отключено в демо-версии

```
Вход: Docker образы из CI/CD pipeline
Обработка: Автоматическая валидация через Kubernetes Admission Webhook
Выход: Allow/Deny решение с детальным аудитом
```

## Критические проблемы, которые решает проект

### 1. Уязвимости в контейнерных образах

#### Проблема
- **Массовое использование уязвимых базовых образов**: Alpine, Ubuntu, Debian с известными CVE
- **Устаревшие пакеты**: Отсутствие timely обновлений зависимостей
- **Supply Chain Attacks**: Компрометация образов в registry или на этапе сборки
- **Runtime уязвимости**: Эксплуатация уязвимостей после развертывания

#### Решение системы
```yaml
# Пример блокировки неподписанного образа
Admission Decision: DENY
Reason: Image signature verification failed - unsigned image not allowed in production
Violations:
- signature_required: Production environment requires signed images
- untrusted_registry: Image from untrusted registry
```

### 2. Отсутствие traceability цепочки поставок

#### Проблема
- **Неизвестное происхождение образов**: Кто собрал? Когда? Из какого кода?
- **Отсутствие цифровых подписей**: Невозможность верифицировать целостность
- **Man-in-the-Middle атаки**: Подмена образов в registry
- **Неавторизованные изменения**: Модификация образов после сборки

#### Решение системы
```json
{
  "signature_verified": true,
  "signer": "CN=cosign,O=GitHub Actions",
  "timestamp": "2024-01-01T10:30:00Z",
  "certificate_chain": "Fulcio->Rekor->Image",
  "provenance": {
    "build_system": "GitLab CI",
    "repository": "mts/backend-service",
    "commit": "a1b2c3d...",
    "workflow": "security-build.yaml"
  }
}
```

### 3. Нарушения compliance и регуляторных требований

#### Проблема
- **PCI DSS**: Требования к защите платежных данных
- **GDPR**: Защита персональных данных в контейнерах
- **ФСТЭК**: Российские стандарты криптографической защиты
- **Отсутствие аудита**: Невозможность доказать compliance

#### Решение системы
```rego
# OPA Policy для PCI DSS compliance
package policies.pci_dss

allow if {
    # Требования к шифрованию
    input.image.encryption_enabled == true

    # Запрет privileged режимов
    not input.pod.spec.containers[_].securityContext.privileged

    # Resource limits обязательны
    input.pod.spec.containers[_].resources.limits != null

    # Audit logging включен
    input.pod.metadata.labels["pci-dss"] == "compliant"
}
```

### 4. Риски телеком-инфраструктуры

#### Специфические риски МТС
- **Масштаб воздействия**: Миллионы абонентов зависят от сервисов
- **Критичность downtime**: Финансовые потери, репутационные риски
- **Государственная инфраструктура**: Дополнительные требования безопасности
- **IoT и 5G**: Новые поверхности атаки через edge computing

#### Телеком-специфические угрозы
- **SS7 vulnerabilities**: Уязвимости в сигнальных протоколах
- **DDoS amplification**: Через compromised контейнеры
- **Data exfiltration**: Утечка абонентских данных
- **Service disruption**: Отказ в обслуживании через контейнеры

### 5. Проблемы CI/CD интеграции

#### Проблема
- **Долгое время сборки**: Сканирование замедляет pipeline
- **False positives**: Блокировка безопасных развертываний
- **Отсутствие feedback**: Разработчики не знают о проблемах
- **Manual overrides**: Обход проверок безопасности

#### Решение системы
```yaml
# Оптимизированный CI/CD pipeline
stages:
  - build
  - parallel:  # Параллельное выполнение
      - security_scan
      - unit_tests
      - integration_tests
  - sign_and_push
  - deploy

security_scan:
  stage: security_scan
  script:
    - scan_image --fast-mode  # < 30 секунд
    - sign_image --keyless    # Автоматическая подпись
  artifacts:
    reports:
      container_scanning: scan-results.json
  allow_failure: false  # Критическая проверка
```
