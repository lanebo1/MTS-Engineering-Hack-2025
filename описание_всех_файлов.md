# Описание всех файлов проекта системы безопасности контейнеров МТС

## Корневые файлы проекта

### `README.md`
Основная документация проекта на русском языке. Содержит подробное описание системы безопасности контейнеров для МТС, включая:
- Обзор задачи и ключевые возможности
- Подробную архитектуру с диаграммами Mermaid
- Технологии и инструменты
- Инструкции по быстрому запуску
- Мониторинг и метрики
- Политики безопасности
- Руководство по тестированию и troubleshooting

### `architecture.md`
Детальное описание архитектуры системы безопасности:
- Компоненты системы (Trivy*, Cosign, OPA, Admission Webhook) *Trivy отключен в демо-версии
- Поток данных и интерфейсы взаимодействия
- Диаграммы Mermaid с визуализацией архитектуры
- Безопасность и compliance требования для МТС
- Регуляторные требования (GDPR, ФСТЭК, PCI DSS)

### `architecture_diagram.md`
Визуальная архитектура системы с подробными диаграммами:
- Высокоуровневая архитектура
- Диаграмма развертывания в Kubernetes
- Детальная диаграмма компонентов
- Диаграмма последовательности
- Диаграмма CI/CD процесса

### `BEGINNER_GUIDE.md`
Пошаговое руководство для начинающих пользователей:
- Проверка и установка зависимостей (Docker, kubectl, Go)
- Запуск системы через Docker Compose или Kubernetes
- Тестирование всех функций
- Просмотр метрик и мониторинга
- Решение проблем (troubleshooting)
- Чек-лист проверки работоспособности
- Очистка после тестирования

### `interfaces.md`
Документация API интерфейсов всех компонентов:
- Trivy Scanner API (сканирование уязвимостей) *отключено в демо-версии
- Cosign Signature API (подписание и верификация)
- OPA Policy Engine API (оценка политик)
- Admission Webhook API (Kubernetes integration)
- Monitoring API (Prometheus метрики)
- Notification API (Telegram/Slack)
- Протоколы коммуникации и обработка ошибок

### `go.mod` и `go.sum`
Стандартные файлы управления зависимостями Go:
- `go.mod`: Определяет модуль container-security-mts с зависимостями Prometheus, Zap logger, YAML парсер, Kubernetes API
- `go.sum`: Контрольные суммы зависимостей для обеспечения целостности

## Исходный код Go (директория `cmd/`)

### `cmd/trivy-scanner/main.go`
Главная точка входа для сервиса сканирования Trivy:
- HTTP сервер с REST API для сканирования образов
- Конфигурация через флаги командной строки
- Graceful shutdown
- Middleware для логирования запросов
- Health check эндпоинты (`/health`, `/ready`)
- API эндпоинт `/api/v1/scan` для запуска сканирования

### `cmd/webhook-server/main.go`
Главная точка входа для admission webhook сервера:
- Интеграция всех компонентов (Trivy*, Cosign, OPA) *Trivy отключен в демо-версии
- Поддержка TLS и HTTP режимов
- Метрики через Prometheus
- Telegram/Slack уведомления
- Health check и readiness эндпоинты
- Graceful shutdown для всех серверов

## Внутренние компоненты (директория `internal/`)

### `internal/scanner/scanner.go`
Реализация сканера Trivy *(отключен в демо-версии)*:
- Структуры данных для запросов и результатов сканирования
- Интерфейс к команде `trivy image scan`
- Парсинг JSON результатов Trivy
- Управление кэшем и базой данных уязвимостей
- HTTP API для обработки запросов сканирования
- Валидация входных данных и обработка ошибок

### `internal/cosign/verifier.go`
Реализация верификации подписей Cosign:
- Проверка цифровых подписей контейнерных образов
- Поддержка keyless signing (OIDC) и традиционных ключей
- Парсинг результатов верификации
- HTTP API для обработки запросов
- Обработка ошибок неподписанных образов

### `internal/opa/evaluator.go`
Интеграция с OPA (Open Policy Agent):
- Оценка политик безопасности на языке Rego
- Локальная и удаленная оценка политик
- HTTP API для взаимодействия с OPA сервером
- Fallback на локальную оценку при недоступности сервера
- Парсинг результатов политики

### `internal/notifications/notifier.go` и `types.go`
Система уведомлений:
- `notifier.go`: Интерфейс для отправки уведомлений (Telegram, Slack)
- `types.go`: Структуры данных для уведомлений (типы событий, severity, детали)

## API интерфейсы (директория `pkg/api/v1/`)

### `pkg/api/v1/types.go`
Общие типы данных для API:
- Структуры для admission webhook (AdmissionWebhookRequest/Response)
- Типы для результатов безопасности (SecurityScanResult, SignatureVerificationResult)
- Типы политик (PolicyEvaluationRequest/Result)
- Конфигурационные структуры (WebhookConfig)

### `pkg/api/v1/webhook.go`
Основная логика admission webhook:
- Обработка Kubernetes AdmissionReview запросов
- Валидация подов перед развертыванием
- Интеграция с Trivy*, Cosign и OPA *Trivy отключен в демо-версии
- Извлечение образов из подов
- Определение контекста развертывания (environment, team)
- Обработка ошибок и уведомления

### `pkg/api/v1/handlers.go`
Обработчики HTTP запросов:
- Общие обработчики для health check
- Middleware для логирования
- Валидация запросов
- Стандартизированные ответы об ошибках

### `pkg/api/v1/policy.go`
Управление политиками безопасности:
- Загрузка и применение политик OPA
- Валидация политик
- Управление версиями политик

### `pkg/api/v1/scan.go`
Обработчики для сканирования:
- API для запуска сканирования образов
- Форматирование результатов
- Кэширование результатов сканирования

## Утилиты (директория `pkg/utils/`)

### `pkg/utils/config.go`
Управление конфигурацией:
- Загрузка конфигурации из файлов YAML/JSON
- Переменные окружения
- Валидация конфигурации

### `pkg/utils/logging.go`
Система логирования:
- Интеграция с Zap logger
- Структурированное логирование
- Уровни логирования (debug, info, warn, error)
- JSON формат для production

### `pkg/utils/metrics.go`
Метрики Prometheus:
- Счетчики для сканирований, блокировок, верификаций
- Гистограммы для времени обработки
- Метки для категоризации метрик
- HTTP handler для экспорта метрик

## Политики безопасности (директория `policies/`)

### `policies/vulnerability_policy.rego`
Политика блокировки образов с уязвимостями:
- Блокировка критических уязвимостей (CVSS >= 9.0)
- Блокировка образов с высоким риском (CVSS >= 7.0)
- Определение причин блокировки и severity
- Идентификаторы политик для аудита

### `policies/base_image_policy.rego`
Политика разрешенных базовых образов:
- Список одобренных базовых образов (Alpine, Ubuntu, etc.)
- Проверка использования разрешенных образов
- Исключения для development сред
- Разные уровни severity для разных сред

### `policies/compliance_policy.rego`
Политики соответствия требованиям:
- Проверка compliance с PCI DSS, GDPR
- Требования к resource limits
- Проверка security context
- Политики для разных сред (dev/staging/prod)

### `policies/signature_policy.rego`
Политики для цифровых подписей:
- Обязательная проверка подписей в production
- Keyless signing требования
- Проверка срока действия подписей
- Исключения для доверенных registry

### `policies/container_security.rego`
Общие правила безопасности контейнеров:
- Проверка privileged режимов
- Resource limits и requests
- Network policies
- Volume mount restrictions

### `policies/data.json`
Статические данные для политик:
- Списки разрешенных образов
- Конфигурационные параметры
- Справочные данные для compliance

### `policies/test_scenarios.json`
Тестовые сценарии для валидации политик:
- Примеры входных данных
- Ожидаемые результаты
- Краевые случаи для тестирования
